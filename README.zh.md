# MemoryBridge — 面向 AI Agent 的行为遥测基础设施

> 一条通向 Agent 感知的轻量级行为事件流。移动端行为 → 结构化事件溯源 → LLM 驱动的状态推理。零硬编码规则，零 if-else。

---

## 是什么

MemoryBridge 是一个**行为事件摄入层**，专为自主 AI Agent 设计。

它不是监控工具，不是控制工具，也不是效率工具。它是 Agent 的"感官"——让 Agent 能感知用户在移动设备上的行为模式，而不仅仅依赖 prompt 输入。

---

**核心设计分离**：系统将**感知**（确定性，事件摄入）与**推理**（概率性，AI 驱动）彻底分离。摄入层保证数据完整性和时序一致性。推理层拥有所有解释权。

## 四个核心概念

### 1. Agent 感知层

这是自主 AI Agent 连接真实世界的输入面。与传统 prompt-only 交互不同，本系统提供**持续行为事件流**——你的 Agent 能"看到"用户在做什么，而不仅仅听到用户说什么。

- **行为传感器** → 移动端自动化（iOS 快捷指令、Android Tasker），在 App 生命周期变化时发出结构化事件
- **事件摄入网关** → 轻量 HTTP 端点，接收、校验、加时间戳
- **Agent 可消费输出** → 时间序列行为数据，可直接注入 LLM 上下文

### 2. Agent 记忆的事件溯源

系统为 Agent 状态重建提供了结构化事件溯源原语：

- **只追加事件日志** → 每个事件不可变、带时间戳、可追溯
- **Session 重建** → 打开/关闭事件配对，解析为包含时长、时间点、序列信息的可量化行为会话
- **时间窗口查询** → `?period=today | week` 返回按任意时间边界切片的聚合遥测
- **行为聚合** → 打开次数、关闭次数、会话数、总时长、单次会话分解、小时分布——全部从原始事件推导，不存储预计算状态

### 3. 零规则的 AI 决策层

**没有规则引擎**。没有 YAML 条件。没有时间窗口触发器。没有阈值 if-else。

| 传统方案 | MemoryBridge |
|---|---|
| `if 打开次数 > 5 then 通知` | Agent 读取打开次数相对基线的偏离，评估趋势方向 |
| 硬编码冷却时间 | Agent 根据对话上下文决定何时发言 |
| 规则 YAML → 推送 | 裸遥测 → LLM 推理 → 自然语言提醒 |
| 开发者定义阈值 | 模型自推断行为常态 |

**系统责任**：忠实记录事件，计算正确的时序状态，暴露可查询数据。
**Agent 责任**：周期性消费行为遥测，交叉参照长期记忆，判断是否有模式需要人类关注。

### 4. Agent 心跳 / 可观测流

心跳不是 cron job——它是**面向自主 Agent 的周期性行为遥测流**。

每 30 分钟，Agent：

1. 拉取今日遥测（`/stats?period=today`）
2. 拉取本周趋势（`/stats?period=week`）
3. 对照存储于 Agent 记忆中的个人基线进行分析
4. 决策：静默确认（`HEARTBEAT_OK`）或自然语言提醒

Agent 在开口前评估五个维度：

- **趋势方向**——使用量在攀升还是下降？
- **异常评分**——今日会话时长是否超出个人 z-score 范围？
- **时间分布**——会话是否聚集在深夜时段？
- **新颖度检测**——事件流中是否出现了之前未见过的 App？
- **缺席信号**——通常活跃的 App 是否完全消失？

## API

### 事件摄入

```
POST /hook
```

**事件结构：**

```json
{
  "app": "douyin",
  "event": "open",
  "time": "2026-05-21T12:00:00+08:00"
}
```

**事件类型：**

| 类型 | 语义 |
|---|---|
| `open` | App 进入前台——开始一个行为会话 |
| `close` | App 进入后台——终止当前会话 |
| `lock` | 设备锁定——终止所有活跃会话 |
| `unlock` | 设备解锁——重置会话上下文 |
| `heartbeat` | 行为传感器的存活脉冲 |

事件摄入是 **fire-and-forget**——不评估规则、不派发通知。只记录并确认。

### 时序状态查询

```
GET /stats?period=today
GET /stats?period=week
GET /stats?app=douyin&period=today
```

**返回：**

```json
{
  "douyin": {
    "date": "2026-05-21",
    "opens": 8,
    "closes": 6,
    "sessions": 5,
    "total_sec": 7200,
    "total_min": 120.0,
    "session_details": [
      {"time": "2026-05-21T12:30", "dur_sec": 1800},
      {"time": "2026-05-21T14:05", "dur_sec": 1200}
    ]
  }
}
```

每个会话时长由原始的 open/close 事件对推导——无预聚合指标，无估算启发式。

### 健康检查

```
GET /health
```

## 事件流模型

事件存储是**只追加的时间序列日志**，不是应用状态。

```json
{
  "events": [
    {
      "id": "evt_20260521_120000_a1b2c3",
      "app": "douyin",
      "event": "open",
      "timestamp": 1747800000,
      "iso_time": "2026-05-21T12:00:00+08:00",
      "date": "2026-05-21"
    }
  ]
}
```

**设计属性：**

- **不可变**——摄入后事件永不修改
- **可回放**——完整事件流可重建任意历史行为状态
- **自清理**——7 天保留窗口，自动滚动
- **无状态服务**——摄入网关不持有任何内存中的应用状态；事件文件是唯一真相源

## AI Agent 集成

### 与 OpenClaw 原生集成

本系统设计为 OpenClaw Agent 运行时的配套服务。心跳通过 `curl /stats` 拉取遥测，交叉参照 `MEMORY.md` 中的个人基线，仅在确实需要时生成自然语言观察。

### 作为工具适配器（可扩展）

摄入 + 查询模式可适配其他 Agent 框架：

- **MCP（模型上下文协议）**——将 `/stats` 暴露为带 `period` 和 `app` 参数的 `tool`
- **LangChain**——将查询 API 封装为行为分析的 `Tool`
- **自定义 Agent**——任何能发 HTTP 请求的 Agent 都可以消费遥测端点

### 事件回放 / 数据集能力

只追加事件流同时可作为行为数据集。历史事件可回放给 Agent 用于：

- 行为模式发现
- 基线校准
- 异常检测模型训练

- **多设备遥测网格**——合并来自多个传感器（手机、平板、手表）的事件流为统一的行为时间线
