# 开发计划

## 目标

保留现有原版 `Shortcut Server` 功能，同时新增中间层 JSONL 存储和查询 API，以支持智能体后续读取分析。

---

## 现有功能保留方案

保留当前的：

- `load_events()`
- `save_events()`
- `today_str()`
- `compute_stats()`
- `/hook`
- `/stats`
- `/health`

这样可以保证原有 `Shortcut Server` 行为继续可用，同时新增中间层设计。

---

## 需要改造的函数

### 1. `hook()`

- 保持兼容老版 `/hook` 接收旧 payload。
- 将旧事件继续写入现有 `data/events.json`，保持原统计逻辑。
- 同时调用共享存储方法，将事件按新设计追加到 JSONL 文件。

逻辑思路：

- 解析 `app` / `event` / `time`；
- 生成标准事件对象；
- 写入旧版 `events.json`；
- 转换为新 schema 的 JSONL 事件，并追加到 `/data/events/{device_id}/{date}.jsonl`。

### 2. `compute_stats()`

- 继续保留当前按 `app` 的统计逻辑。
- 未来可扩展为从 JSONL 读取 `app_opened` 事件。

逻辑思路：

- 目前保持读取 `events.json`；
- 如果后续需要，可增加支持从 JSONL 事件中提取 `app_opened` 类型数据作为补充。

## 新增函数

### 3. 存储路径与工具函数

- `get_device_events_dir(device_id)`
  - 返回 `/data/events/{device_id}` 目录路径。
  - 负责目录存在性检查与创建。

- `get_jsonl_path(device_id, date_str)`
  - 返回按天分片的文件路径，如 `/data/events/A1B2C3/2026-05-22.jsonl`。

- `parse_iso_timestamp(timestamp_str)`
  - 校验并解析 ISO 8601 时间字符串，返回 `datetime` 对象。
  - 失败时抛出或返回错误，便于请求参数验证。

- `event_date_str_from_timestamp(timestamp_str)`
  - 将 ISO 时间转换成 `YYYY-MM-DD`，用于 JSONL 文件名。

### 4. JSONL 写入与读取

- `append_event_jsonl(event)`
  - 将一个完整事件写入对应设备、对应日期的 JSONL 文件。
  - 每次写入一行 JSON，避免覆盖已有数据。

- `read_events_jsonl(device_id, from_date=None, to_date=None)`
  - 按日期范围读取多个 JSONL 文件。
  - 返回事件数组，支持流式解析与过滤。

- `read_latest_event(device_id, event_type=None)`
  - 读取指定设备最新的事件。
  - 如果提供 `event_type`，返回该类型最新一条。

### 5. API Key / 认证

- `require_api_key()`
  - 可选的请求验证函数。
  - 检查 `X-API-Key` 是否存在且合法。
  - 如果配置了密钥，则保护写入接口。

## 新增 API 端点

### 6. `POST /api/events`

- 新增统一接收端点。
- 请求体字段：
  - `device_id`
  - `event_type`
  - `timestamp`
  - `data`
- 逻辑：
  - 解析并校验字段；
  - 解析 `timestamp` 为 ISO 时间；
  - 可选认证；
  - 写入 JSONL；
  - 返回标准成功 JSON。

### 7. `GET /api/events/<device_id>`

- 按设备返回事件数组。
- 支持查询参数：
  - `from=YYYY-MM-DD`
  - `to=YYYY-MM-DD`
- 逻辑：
  - 读取对应日期范围内 JSONL 文件；
  - 拼接事件数组返回。

### 8. `GET /api/events/<device_id>/latest`

- 返回最新一条事件。
- 支持可选参数：
  - `event_type=scheduled`
- 逻辑：
  - 从对应设备最近日期文件中倒序查找；
  - 返回最新匹配事件。

## 数据存储格式改造

### 9. JSONL 存储

- 根目录：`/data/events/{device_id}/`
- 文件名：`YYYY-MM-DD.jsonl`
- 每行为完整请求体 JSON

### 10. 兼容旧存储

- 仍保留当前 `data/events.json` 作为老版本兼容。
- 新事件同时写入 JSONL，避免拆分后丢失历史。

## 代码改造思路

1. 先在 `server.py` 中增加 JSONL 存储工具。
2. 在现有 `hook()` 中增加兼容写入与共享存储调用。
3. 新增 `/api/events` 接口，按文档严格校验新 payload。
4. 新增查询接口 `GET /api/events/...`。
5. 保持 `/stats`、`/health` 不变，继续支持旧版使用场景。
6. 如果 `X-API-Key` 存在则启用认证，否则默认开放写入。
